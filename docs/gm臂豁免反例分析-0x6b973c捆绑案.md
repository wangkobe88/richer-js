另有一个 G4 门的结构性缺口:**回测 vs 实跑不对称**。回测里 `gmgnRisk` 是 analyze 当次查的**当前** GMGN 数据(10-05 的票 10-11 回测,GMGN 早已索引 → covered=1);实跑开盘 11 秒 GMGN 大概率未索引 → covered=0 → fail-open 放行。**G4 门的高效力只存在于回测,实跑对 fresh 票几乎恒放行**。

### tokenScore 1.861 构成分解

```
桶分布:zhuang 52.05%(10 钱包,均分 2.358)+ neutral 47.95%(均分 1.321)+ retail 0 + new_wallet 0
tokenScore = 0.5205 × 2.358 + 0.4795 × 1.321 ≈ 1.861
```

关键机制:**2.2 新钱包中性分只对 `source==='realtime'`(画像 miss、当场现算)生效**。这批钱包 offline 库全有行(tc=46-77、秒级持仓、小额密集),四维度实打实评分落在 1.3~2.4 区间,无兜底。**低分是画像的真实输出,TPA 旧口径的 block 是正确的。**

### 「困在 GMGN 上分数不该低」直觉的校正

该推理描述的是 **trader 口径时代**的形状(所有行合并成 GMGN 路由一个地址,画像 miss → realtime → 2.2 兜底)。二期(9d18253)切 wallet 口径后 sender 拆开,各自有独立画像——**有 offline 行就不吃中性分**。wallet 口径恰恰是把工作室钱包拆出来暴露真实低分的一步,这一步是对的。

## 五、结论与修正方向

### 结论

1. 画像构建、评分、旧口径 TPA 判定**全部正确**(1.861 → block,五臂避亏);
2. gm 臂总体战绩(2026-10-11 四臂对照:gm +21.58 vs b2 +14.64,豁免救回 38 票 +13.58、胜率 76%)说明**豁免方向平均上是赚的**——问题不是豁免整体错,而是 `gmgnUserPct` 单维度区分不了两种高占比成因:
   - **真散户热度盘**:金额大小不一、时间自然分散、钱包画像多样 → 豁免是对的;
   - **捆绑伪装盘**(本案):同秒等额批次、uniform 簇 50%、batch 钱包秒级持仓 → 豁免把作弊洗白。
3. 「GMGN 用户 = 真实散户」的等式下得太满:GMGN 通道里混着批量工作室钱包(本案 22/26)与快枪手(首买)。

### 修正候选(按贴合度排序,待用户裁定)

1. **豁免前置门 = 被剔除群体的画像质量**(最贴 TPA 本身):豁免生效前先算被剔除 GMGN 群体的画像聚合——medianHold(秒级?)、桶均分、tc 分布。秒级持仓 + 低分形状 → 不豁免,回落 tokenScore 原判(本案即回落 1.861 被拦);
2. **uniformBuy 簇门**:豁免条件追加 `earlyTradesUniformBuyClusterRatio < 阈值`。因子已计算未引用,零新采集成本,且实跑/回测同效(零外部依赖)——顺带补 G4 门实跑时效缺口;
3. **G4bundler 门方向复核**:220 票扫描里「低 bundler 拦/高 bundler 放」是否把伪相关当了真;
4. 人数门/top1 门对 sybil 的联合失明:「分散=健康」假设在 GMGN 批量路由时代需重审(拉长线课题)。

## 六、验证结果(2026-10-12,口径均为 FIFO 时间序修复 + 窗口对齐 T=10-07 15:08Z)

### 6.1 uniform 前置门:否决(修正候选 2 不成立)

`tmp_gmgn_exempt_uniform.cjs`(182)分桶+阈值模拟,关键发现是 **trades 行 id 序 FIFO 虚高坑**:id=bigserial 分配序≠提交序(回测攒批落库),sell 行 id 可先于 buy → 未配对落袋+成本留存,notpa 实测虚高 +30.6。全部对拍脚本已切 `(created_at,id)` 时间序(`tmp_gmgn_pair_gm.cjs` 旧数字同样虚高,差分方向仍有效)。

修复后:**所有 uniform 阈值档位都是净负效应**——X=30% gm 臂 −4.60 / notpa −3.79;X=50% −1.63 / −1.37;X=20% −10.41 / −16.60。高 uniform 桶平均净正(notpa [30,50%) 34 票 +2.43 胜 50%;gm 豁免票 [30,50%) 26 票 +2.97 胜 58%)。用户洞察定量成立(0xac5174ec0623c09fd76fb1483a91f5e60e897777 案):**前期作弊者卖掉后散户接盘又起来的票是赚的,为 0x6b973c 这类少数真作弊票加门,放弃的赢票更多**。

### 6.2 TPA tokenScore 门本身:全档负效应零区分度(`tmp_tpa_gate_effect.cjs`)

四臂对齐对拍(同源 3e57ed75 系,b2 vs tnone 唯一差异 = condition `TPAPre_tokenScore > 2.5`):

| 臂 | 买 | 净额 |
|---|---|---|
| tnone(无门,TPA 照跑) | 129 | **+21.25** |
| notpa(TPA 不激活) | 129 | +20.45 |
| gm(剔除+豁免60) | 107 | +16.09 |
| b2(门 2.5) | 69 | +13.49 |

- 门拦截 60 票:放弃赢 31 票 **+9.93** / 避免亏 29 票 **−2.94** → 门净效应 **−6.99**;拦截票胜率 52% = 放行票胜率 52%,分数零区分度;
- 阈值曲线全档负单调恶化:score≥0.8 拦 5 票 −0.84 / ≥1.5 −1.12 / ≥2.0 −3.25 / ≥2.5 −6.99——**没有任何档位正效应**;
- 案例票定位:0xac5174ec score 2.589 过门放行 +0.856(散户接盘票);0x6b973c score 1.861 被拦避 0.21 ✓——但 as-of 分数区分不了两者与 0xa67a200c(score **0.511** 赚 +0.685)/0x5eff423c(1.572,+1.286) 的分布重叠。**「拦捆绑作弊」用 TPA 分数达不到,需要作弊形状本身(同秒等额批次等时间维度)的信号,是独立新课题**。

数据建议 notpa(不激活);最终去留待用户裁定(用户方向输入:「TPA 直接豁免去除可能不对」「前期持有者有问题不能否定票」——两句话在数据上分别对应避亏 −2.94 的真实性与放弃赢 +9.93 的代价,金额比 1:3.4)。
